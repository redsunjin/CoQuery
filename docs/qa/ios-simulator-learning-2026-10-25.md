# iOS 학습 흐름 시뮬레이터 검증 — 2026-10-25

## 환경과 방법
- 시작 기준: main b94bba2, Capacitor 8.4.3. 수정 브랜치: fix/ios-simulator-learning-qa.
- Xcode 27.1, Release/arm64 시뮬레이터 빌드, 서명 없음. iPhone 17e / iOS 27.0의 실제 설치 앱(capacitor://localhost)에서 검증했다.
- XcodeBuildMCP로 빌드·설치·실행·스크린샷을 확인하고, serve-sim의 WebKit 검사 도구를 통해 실제 WKWebView 안의 DOM 버튼과 input/change/submit 이벤트로 흐름을 실행했다. 데스크톱 브라우저의 동일 페이지로 대체하지 않았다.
- 접근성 도구는 웹뷰 버튼을 노출하지 않았고, 미러의 HID 터치는 기록되지만 화면 전환으로 확인되지 않았다. 따라서 **손가락 터치·키보드 사용성, VoiceOver 검증 완료를 주장하지 않는다.** 도구 문제인지 앱의 입력 처리 문제인지는 확정하지 못했다. 이 항목은 초기 회차의 제약이며, 사용자 잠금 해제 후의 직접 조작 후속 검증 결과는 아래에 구분해 기록한다. 앞선 미반영 입력의 원인까지 확정하지는 않는다.
- iPhone Duo / iOS 27.1에도 설치·프로세스 실행을 시도했으나 화면이 검게 캡처되어 기능 검증 범위에서 제외했다.

## 발견 및 수정
1. 기존 앱은 빌드는 성공하지만 iOS 27.0 실행 직후 종료됐다. 크래시 스택의 `UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption`와 누락된 scene manifest를 확인했다.
   - 단일 UIWindowScene 설정과 SceneDelegate를 추가했다. 기존 Main.storyboard의 CAPBridgeViewController와 웹 UI를 그대로 사용한다.
   - URL 및 사용자 활동을 Capacitor 프록시에 전달하는 초기 연결/실행 중 콜백을 유지했다. 링크 유입 자체의 런타임 검증은 이번 범위에 포함하지 않았다.
2. iOS 번들에 없는 `manifest.webmanifest`를 요청하는 오류를 네이티브 웹뷰 콘솔에서 확인했다.
   - iOS HTML 생성 단계에서만 PWA manifest 링크를 제거했다. 웹 PWA의 원본 HTML·manifest·서비스 워커는 변경하지 않았다.

실제 AI·서버·다른 참여자와 연결하지 않았다. 참여형 데이터는 모의이며 페이지 전환 시 소멸한다. 실사용자·미성년자 대상 검증, 실기기, 모든 iOS 버전, 터치·접근성·회전·배경 복귀의 종합 검증은 수행하지 않았다. 런타임에 Capacitor의 일반적인 `JS Eval error A JavaScript exception occurred` 1줄과 시뮬레이터 WebKit 접근성 클래스 중복 경고가 남았으며, 이 문구만으로 기능 오류의 원인을 확정하지 않았다. 실제 학습 결과 검증 중 관찰된 JavaScript error/unhandledrejection 이벤트는 없었다.

## 회귀 검사와 리뷰

- 원격 검사 및 병합 결과는 PR에서 확인한다. 배포·앱스토어 제출은 수행하지 않는다.

## 잠금 해제 후 직접 조작 후속 검증
사용자가 Mac 잠금 해제를 알린 뒤 같은 iPhone 17e / iOS 27.0에서 Device Hub의 화면 터치와 키보드 캡처, XcodeBuildMCP 터치 스크롤로 검증했다. 아래 결과는 DOM click/value 대입을 사용하지 않았다.

- SQL: 이어서 학습하기 → 두 번째 문제에서 영문 SQL 키보드 입력. 불필요한 id 열을 반환한 오답의 피드백·Retry를 확인하고 `SELECT name, segment FROM customers ORDER BY id`로 수정해 정답·4행·시도 저장을 확인했다. 재실행 후 홈 진행률 2/24가 유지됐다.
- C1: A 카드 선택 → 정답 → 설명 `A matches both rules.` 입력·저장 확인.
- C2: A·C만 선택한 오답 → B를 추가 선택한 정답으로 전환 확인.
- R1: 숫자 3 입력 → 예상/실제 3행 및 정답 확인.
- U1: iOS 기본 선택 메뉴에서 2점 이상 → 신규만 선택 → 예상 전체 2·신규 2 입력 → 목표 충족 확인.
- 참여형: 기본 질문 등록 → 모의 검사 → 사람 발행 대기 → 승인 → 주장·근거·반례·대안 영문 직접 입력 → 답변 검토 대기·승인 → 요약 생성·사람 확인 → 신고 이유 입력·접수 → M1 임시 비공개 → 항소 이유 입력·독립 재심 → M2 원결정 변경·공개 복원 및 감사 이력 11개 확인.
- 직접 조작 검증은 대표 퍼즐 C1/C2/R1/U1에 한정한다. 9개 전체의 계산·전이는 위 WKWebView 내부 이벤트 검증과 계약 검사 결과다. 9개 모두를 손으로 다시 풀었다고 해석하면 안 된다.
- 한국어 문장을 도구로 자동 타이핑했을 때 영문만 전달되어 한국어 키보드 조합 검증은 미완료다. 한국어 표시 및 기존 한국어 기록 복원은 확인했다. VoiceOver·실기기·전체 OS·모든 화면 방향 검증은 여전히 미수행이다.

### 후속 발견과 최소 수정
1. 참여형 상단 브랜드·SQL 홈 링크가 상태 막대에 겹쳤다. viewport-fit=cover와 상단/좌우 safe-area, 하단 safe-area, 헤더 줄바꿈을 적용했다. 재빌드 앱에서 상태 막대 아래에 브랜드·홈 링크가 모두 표시되는 것을 확인했다.
2. 모바일 입력 포커스 뒤 자동 확대가 남아 화면 가장자리가 잘렸다. 개념/모의 체험 폼에만 모바일 글자 크기 16px을 적용했다. 최종 재빌드 앱의 질문 입력 포커스에서 가로 확대·잘림이 재발하지 않음을 확인했다. 사용자의 확대 기능을 금지하는 설정은 추가하지 않았다.

기존 색상·카드·학습 경로와 제품 계산/저장 로직은 바꾸지 않았다. 최종 Release 빌드·실행, rc:verify 전체, 9개 퍼즐 계약 및 iOS 자산 검사가 통과했다. 자체 변경 검토를 수행했으며 별도 사람·독립 에이전트 승인 리뷰는 수행하지 않았다. 원격 CI 및 병합 상태는 후속 PR에서 확인한다. 배포·앱스토어 제출 없음.
