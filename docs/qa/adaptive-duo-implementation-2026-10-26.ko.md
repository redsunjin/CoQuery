# 탐구 좌우 배치·iPhone Duo 실행 검증

2026-10-26 KST. 기준 main 3ff318e, 별도 codex/adaptive-exploration-duo. **기능 검증용 내부 베타**를 유지한다. 실제 사용자 관찰·학습 효과·물리 기기 검증과 구분한다.

## 구현

- 예상·실험, 새 상황 적용, 창작 화면에서 같은 컨트롤을 좌우로 재배치한다. 왼쪽 조작/편집과 오른쪽 결과/근거/미리보기를 나란히 표시한다. 입력 폼을 복제하거나 크기 변화 때 렌더링하지 않는다.
- 컨테이너의 가용 폭이 충분할 때 두 영역, 작은 창에서는 한 열이다. 충분한 화면에서는 ‘이어 보기’도 선택할 수 있으며 클릭은 CSS 상태만 바꾸고 학습 기록을 변경하지 않는다. 설명 중심 단계는 읽기 폭을 유지한다.
- 높이가 짧은 화면은 6개 단계 버튼 대신 현재 단계 선택기를 제공한다. 844×390에서 첫 카드 top=311, bottom=387로 카드 전체가 첫 화면 안에 보인다. 기존 검토의 top=554보다 접근성이 개선됐다. 실제 사람의 사용성 측정 결과는 아니다.
- 창작 편집 시 미리보기를 갱신하고 이전 결과를 지운다. 실험 전에는 정답 대신 안내만 보여 준다. 초안과 마지막 저장본 구분 및 복원은 유지한다.
- iOS의 기존 Capacitor 컨트롤러를 상속한 AdaptiveBridgeViewController를 연결했다. 실제 웹뷰 크기와 safeAreaInsets를 CSS에 전달한다. iOS 27.1에서는 reservedRegions(kind:.division)도 전달하며 이전 iOS에는 없는 API를 호출하지 않는다. 메시지 핸들러는 주 프레임의 준비 메시지만 받으며 약한 소유자 참조를 사용한다.
- native 포인트→CSS 좌표의 배율과 작업 영역 시작 위치를 반영해 활성 세로 접힘 영역에 간격을 둔다. 양쪽 공간이 최소 폭에 못 미치면 강제 분할하지 않는다. 측면 시스템 영역과 언어 버튼이 겹친 문제를 창 안전 여백으로 수정했다. 가림 영역 전체와 상하 접힘의 특수 배치까지 구현 완료한 것은 아니다.
- PWA 캐시는 v15, 변경한 개념 CSS·탐구 스크립트 URL도 v15로 갱신했다. SQL 계산·24문제 진도·기존 9퍼즐·참여형 모의 동작·빌드 번호는 변경하지 않는다. SQL 집중 모드의 좌우 구성은 후속이다.

## 실제 Duo 전용 시뮬레이터 실행

Xcode 27.1, iOS 27.1, iPhone Duo(`140ABAB1-CCDA-4174-AABF-034CC3AC5CA0`)에서 Debug 빌드·설치·실행 성공. XcodeBuildMCP를 사용했고 서명/업로드/실제 테스터 배정은 하지 않았다. 다른 프로젝트의 전용 시뮬레이터는 대상에서 제외했다.

기본 스크린샷/AX 도구는 비활성 디스플레이를 잡아 검은 캡처와 0개 조작 대상을 반환했다. 이를 앱 빈 화면으로 단정하지 않고 `simctl io enumerate`로 디스플레이를 구분했다. 내부 Screen ID 3과 외부 Screen ID 1을 직접 캡처해 확인했다. Device Hub의 대상 장치와 접힘 각도를 확인한 뒤 화면을 조작했다. 검은 캡처는 통과 증거로 사용하지 않는다.

직접 확인한 흐름:

1. 내부 가로 화면에서 홈→조건 탐구→예상·실험. 결과 미실행 상태의 안내와 두 영역 표시를 확인했다.
2. A 선택 후 접힘 각도 180→0→180. 외부 화면에서 압축 단계 선택기와 A 선택이 남는 것을 확인했다. 다시 펼친 화면에도 A 선택이 유지됐다.
3. 세로 방향으로 전환해 한 열 배치 확인. ‘예상과 결과 비교’를 누르자 내 예상 A/실제 A가 표시됐다. 크기 전환이 새 실험을 자동 실행하지 않는다.
4. 부분 접힘 약101.25도에서 활성 구분 영역 `{x:455.5,y:0,width:40,height:669}`의 네이티브 전달을 로그로 확인했다. 창은 951×669→678×466→951×669 등 실제 변화가 있었고 안전 여백은 측면84/하단34 또는 세로 상단82 등으로 바뀌었다. 이 수치는 이번 시뮬레이터 관찰값이며 하드코딩하지 않는다.
5. 접힘 각도는 시작값 180도로 복원했다. 마지막 자산으로 다시 빌드·설치·실행했다. 화면 증거는 개발 중 대표 장면과 최종 홈 캡처를 구분해 보존한다.

진행 중 선택·계산·창 배치의 대표 경로를 확인한 것이며 모든 자세·반례·저장·입력 조합을 전수 검사한 것은 아니다. native partial 영역 전달과 좌표 계산 통과를 전체 접힘 UX 통과로 확대 해석하지 않는다.

## 남은 검증과 다음 순서

- 실제 Duo의 키보드·한글 조합 중 접기, 선택 범위, 텍스트 편집 초점, VoiceOver 연속 탐색, 두 앱 나란히 사용 양쪽 위치, 영상/카메라 가림 영역, 위아래 접힘, 앱 중단/복귀·오프라인 전수 조합은 미실시다.
- 런타임에 Capacitor의 일반 `JS Eval error` 및 Apple WebKit 접근성 클래스 중복 경고가 관찰됐다. 화면 실행·선택·결과는 동작했지만 원인과 영향 범위를 아직 특정하지 못했다. 모든 런타임 오류가 해소됐다고 주장하지 않는다. 측정·로그 추가 확인 후 출시 관문에서 재판정한다.
- 물리 iPad/iPhone/Duo 검증과 실제 초보자·학생 관찰은 수행하지 않았다. 기존 문서의 관찰 과제에 배치 전환·예상/근거 왕복·창작 수정 과제를 추가해 실시해야 한다. 이번 작업에서 모집 연락은 보내지 않았다.
- 범위 밖: 관계/규칙 전체의 새 창작 여정, SQL 집중 모드 좌우 구성, 실제 AI·운영 커뮤니티. 공개 배포·TestFlight 업로드·App Store 제출/출시도 하지 않았다.

우선순위 1(탐구·창작 적응 배치)과 2(Duo 전용 시뮬레이터의 대표 실행 및 발견 문제 수정)를 진행한 상태다. 완제품/출시 적합성 판정은 실제 기기·접근성·실제 초보자 관문 이후다.
