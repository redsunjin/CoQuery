# iOS 한글 조합 입력·접근성 후속 검증 (2026-10-25)

## 범위와 환경

기준 main: f436abe66d44904349820d48aedb14257548e1cd. iPhone 17e, iOS 27.0 Simulator, Xcode 27.1, Capacitor WKWebView Release 앱에서 진행했다. 실제 사용자 연구나 실제 기기 검증이 아니다. 기존 SQL·9개 퍼즐 로직과 시각 스타일을 유지한다.

## 직접 관찰한 결과

| 항목 | 방법 | 결과 |
| --- | --- | --- |
| 한글 조합 | 참여형 모의 체험의 질문 입력란에서 iOS 두벌식 화면 키보드를 직접 눌러 ㅎ→하→한→한ㄱ→한그→한글 입력 | 통과. 문자열 붙여넣기나 DOM 값 주입을 사용하지 않음 |
| 조합 중 삭제 | 받침 ㄹ 삭제로 한그, ㄹ 재입력으로 한글, 공백으로 확정 | 통과 |

| VoiceOver 활성화 | Device Hub의 접근성 메뉴에서 켜기, 초기 제스처 안내를 이중 탭으로 닫기 | 활성화 및 이중 탭 확인 |
| VoiceOver 포커스 | 질문 화면 제목 선택, 오른쪽 쓸기로 설명과 단계 표시로 이동 | 시각적 포커스 이동 확인 |
| 네이티브 접근성 Audit | Accessibility Inspector에서 CoQuery를 대상으로 실행 | 수정 전·후 Hit Region 경고 모두 7건. 전체 접근성 통과로 판단하지 않음 |
| 수정 후 앱 | 재빌드·실행 후 SQL 홈→개념 퍼즐→참여형 모의 체험 진입 | 통과 |

VoiceOver 음성 출력을 녹음하거나 청취하지 못했다. 한국어 발음, 읽기 내용·순서 전체, 입력 피드백, 로터 탐색, 동적 결과 알림, 모든 SQL·퍼즐·신고·항소 화면의 VoiceOver 완주는 **미검증**이다. 한글 실제 조합 검증은 참여형 질문 입력란에 한정되며 SQL 편집기·퍼즐 설명란의 조합 입력은 별도 확인이 필요하다.

## 발견 사항과 수정

참여형 헤더의 ‘SQL 학습 홈으로’ 링크에서 Inspector가 약 86×17 크기 경고를 제시했다. 기존 색상·글꼴·문구를 유지하면서 링크를 inline-flex로 만들고 최소 너비·높이를 44 CSS px로 보완했다. iOS 번들 계약 검사에 해당 조건을 추가하고 PWA 캐시를 v9로 갱신했다. 학습 판정이나 입력 처리 코드는 바꾸지 않았다.

재검사에서 링크 관련 경고가 약 86×16으로 계속 표시됐다. CSS 상자 확대와 Inspector의 WebAccessibilityObjectWrapper 글자 경계 보고는 서로 다르므로, 이 수정으로 네이티브 경고 또는 VoiceOver 문제가 완전히 해결됐다고 주장하지 않는다. 나머지 6건은 상단 설명 문구 1개와 비대화형 단계 문구 5개에 해당한다. 단계 목록은 버튼이 아닌 정적 ol/li이다. 자동 경고를 무조건 무시하거나 모두 실제 제어 버튼 결함으로 분류하지 않는다.

## 검사와 검토

- npm run ios:sync 성공, Release 시뮬레이터 빌드·실행 성공.
- npm run rc:verify 통과: iOS 생명주기, 9개 개념 퍼즐·규칙 대안, CLI/API, PWA, iOS 번들 및 공백 검사.
- 수정 범위 자체 검토: CSS 터치 상자와 캐시 버전·계약 검사만 변경. 독립된 사람의 접근성 리뷰나 사용자 승인은 수행하지 않았다.
- 검증 중 켠 VoiceOver는 종료 후 끈 상태로 복원했다.

## 남은 검증

실제 iPhone에서 VoiceOver 사용자와 함께 SQL 학습, 각 퍼즐 유형, 질문→검사→답변→요약→신고·항소를 음성·로터로 완주해야 한다. 정답·오답 및 모의 대기·실패 시의 알림, 포커스 복귀와 키보드 가림도 확인해야 한다. Inspector 경고가 남은 링크는 실제 탐색·활성화와 접근성 프레임을 추가 측정한다. SQL 주석·퍼즐 설명의 조합 중 삭제/확정/저장도 확인한다.

실제 AI·서버 연결, 배포 및 App Store 제출은 수행하지 않았다.
