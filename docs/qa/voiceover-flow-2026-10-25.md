# VoiceOver 낭독 자막·포커스 및 전체 기능 흐름 검증

2026-10-25 / 기준 main `9cb23e741d0972a8093d7e46dd78dcd18ceb7679` (PR #29).

## 판정

**전체 VoiceOver 접근성 통과가 아니다.** iOS 시뮬레이터에서 실제 VoiceOver와 자막 패널을 켜고 선택·활성화·포커스와 일부 낭독 문구를 확인했다. SQL·9개 퍼즐·참여형의 전체 기능 흐름은 별도의 로컬 웹 화면에서도 검사했다. 두 결과를 합쳐 iOS에서 VoiceOver만으로 전체 흐름을 완주했다고 주장하지 않는다.

실제 음성은 청취·녹음하지 못했다. 로터 회전과 항목별 탐색도 완료하지 못했다. 이 세션의 도구에는 두 손가락 회전과 세 손가락 스크롤이 없으며, 시도한 외부 키보드 명령에서도 로터 표시를 확인하지 못했다. 이를 시뮬레이터 자체의 미지원 또는 제품 결함으로 단정하지 않는다.

## 환경과 방법

- Xcode 27.1, iPhone 17e / iOS 27.0, Capacitor Release WKWebView.
- 기존 시뮬레이터에서 다른 앱이 표시되는 상태 변경을 발견한 뒤, `CoQuery VoiceOver QA 20261025` 전용 시뮬레이터를 새로 만들어 재검증했다. 상태가 달라진 뒤의 다른 앱 화면을 CoQuery 증거로 사용하지 않았다.
- iOS 설정에서 VoiceOver 켬과 자막 패널 켬을 직접 확인했다. 자막은 VoiceOver가 읽는 텍스트 확인 수단이며 실제 음질·발음 검증의 대체물이 아니다.
- 네이티브 버튼은 위치 선택과 이중 탭으로 활성화했고, 자막과 포커스 테두리를 관찰했다. 화면 키보드 입력에는 접근성 요소 활성화도 사용했다.
- 긴 화면 일부는 VoiceOver를 잠시 끄고 스크롤·입력 준비 후 다시 켰다. 이 구간은 보조 조작을 사용한 기능 확인으로 분류한다. 화면을 보지 않는 사용자의 독립적인 탐색 시험이 아니다.
- 웹 회귀는 새 로컬 포트의 화면에서 수행하여 이전 서비스워커 캐시와 구분했다. 실제 AI나 외부 서버를 연결하지 않았다.

R1의 예측값을 비웠을 때 브라우저가 필수 숫자 필드에 포커스를 유지하는 것도 확인했다. 9개 퍼즐의 기본 수학·관계 판정, 경계와 24개 규칙 조합은 기존 전체 회귀 검사로 별도 확인했다.

## 발견한 문제와 수정

1. **SQL 실행 완료 뒤 결과보다 앞쪽 제목으로 포커스가 돌아감.** 기존 상태 요소에 `role=status`, `aria-atomic=true`, `tabindex=-1`을 추가했다. 빈 입력과 처리가 끝난 경로에서 상태 요소로 포커스를 옮긴다. 새 쿼리·채점·오답 기록 블록이 만들어진 뒤 최종 판정에 도달하도록 한다.
2. **퍼즐 실험·설명 저장 후 새 결과로 포커스가 이어지지 않음.** 결과 제목 또는 저장 완료 문구를 화면에 드러낸 뒤 포커스를 옮긴다. 입력 중 처리와 저장·판정 규칙은 바꾸지 않았다.
3. **참여형 단계 교체 시 버튼이 DOM에서 사라져 포커스가 BODY로 돌아감.** 수정 전 로컬 화면에서 사전 검사 뒤 BODY 포커스를 재현했다. 수정 후에는 유지 가능한 ID가 있으면 해당 입력을 유지하고, 없으면 오류/상태 문구 또는 현재 단계 제목으로 이동한다. 정적 단계 목록에는 현재 단계를 `aria-current=step`으로 표시한다. 단계 목록을 버튼으로 바꾸지 않았다.

기존 색상·글꼴·배치와 SQL·퍼즐·사람 검토의 업무 로직은 유지한다. 프로그램으로 이동하는 포커스 대상은 tabindex=-1이므로 새 Tab 정지점을 추가하지 않는다. 변경된 자산을 전달하도록 PWA 캐시를 v10으로 갱신했다. 기존 Inspector 경고 7건이 해소됐다고 판단하지 않았으며, 이번 최종 빌드의 Audit 건수를 새로 측정한 것은 아니다.

## 검사와 한계

- 최종 소스로 iOS 자산 동기화 및 Release 빌드·실행 성공. 설치된 번들의 퍼즐 스크립트와 원본 일치 확인.
- `npm run rc:verify` 통과: 생명주기·퍼즐·SQL/API·PWA·iOS 번들 및 공백 검사.
- 로컬 브라우저의 실제 UI 조작으로 SQL 상태 3종, 퍼즐 9개 결과·저장 포커스, 참여형 전체 정상 흐름과 요약 실패 복구를 확인했다. DOM 포커스 검사는 음성 낭독·로터 검사를 대신하지 않는다.
- 오디오의 중복 안내 여부, 발음, 언어 자동 전환, 빠른 연속 입력·전환 중 낭독 중단은 확인하지 못했다. role=status와 포커스 이동의 조합은 실제 음성으로도 검토해야 한다.
- 검증 중 켠 VoiceOver·자막 패널·키보드 캡처는 기존 기기와 전용 기기에서 끈 상태로 복원했다. 실제 사용자 검증은 수행하지 않았다.

## 실제 기기에서 남은 승인 조건

아래 항목이 확인되기 전에는 VoiceOver 접근성 완료 또는 출시 준비 완료로 표시하지 않는다. VoiceOver를 사용하는 참여자와 진행하며, 기존 데이터 대신 가상 데이터만 사용한다.

| 시험 | 절차 | 성공 기준 |
| --- | --- | --- |
| 한국어 낭독 | SQL 문제·쿼리·결과 표, 퍼즐 카드·결과·설명, 참여형 상태를 스피커/이어폰으로 청취 | 이름·역할·선택·입력값이 이해되고 필요한 안내가 누락·중복·잘림 없이 전달됨 |
| 로터 | 제목, 링크, 폼 제어, 표를 선택해 양방향 탐색 | 주요 구간을 건너뛰어 도달하고 현재 위치를 이해할 수 있음. 정적 단계가 동작 버튼으로 오인되지 않음 |
| SQL 완주 | 문제 선택→입력→오류 수정→오답→재시도→정답→결과 표→다음 문제→홈 | 좌표 도움 없이 완료, 입력 보존, 판정 안내와 다음 동작이 명확함 |
| 9개 퍼즐 완주 | 각 문제의 필수 실험·두 기준 비교·대안 확인→반례→설명 저장→목록 | 카드 선택·숫자·체크·셀렉트와 관계 표가 탐색 가능하고 결과·저장 뒤 포커스가 적절함 |
| 참여형 완주 | 질문→검사→정제 제안 선택→사람 승인→답변 작성·승인→요약·원문→신고→M1 결정→항소→M2 결정 | 대기·실패·취소를 포함해 좌표 도움 없이 진행. AI 제안과 사람 결정, 원문·요약의 차이를 구별 가능 |
| 기기 환경 | 세 손가락 스크롤·두 손가락 로터, 화면 회전·가림, 음성 중단/복귀·오디오 경로 변경 | 포커스를 잃거나 동작이 막히지 않음. 플랫폼의 촉각·오디오 동작과 함께 사용 가능 |
