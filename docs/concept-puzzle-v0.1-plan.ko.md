## 1. 결정 요약과 근거의 범위

CoQuery를 ‘SQL을 작성하는 학습 도구’에서 ‘조건·관계·규칙을 조작하고 결과를 검증하는 개념 퍼즐 도구’로 확장한다. SQL은 원하는 사람이 나중에 펼쳐 보는 표현 방식으로 남긴다. AI가 답을 대신 쓰더라도 사용자는 무엇을 묻고, 어떤 가정을 바꾸며, 결과를 어떻게 의심할지 배운다.

이 문서는 다음 표기를 사용한다.

- **확인 사실**: 기준 커밋의 코드나 문서에서 직접 확인했다. 저장소의 과거 검증 기록과 이번 실행 결과를 구분한다.
- **제품 제안**: 앞으로 구현·운영할 동작이다. 이미 제공되는 기능이라는 뜻이 아니다.
- **검증 가설**: 사용자 조사나 실험으로 확인해야 하는 예상이다.
- **창의적 가설**: 퍼즐 속 가상 세계나 참여자가 탐색하는 아이디어이다. 현실의 사실로 승인하지 않는다.

이전 대화는 읽었지만 상세한 assistant 답변 대신 참조 표지만 반환되었다. 따라서 과거 세부 결정을 복원했다고 주장하지 않는다. Learn/Practice/Apply/Assist 등 이번 요청에 명시된 방향은 아래 저장소 근거와 연결했다.

## 2. 누구에게 무엇을 제공할 것인가

첫 대상은 SQL 사전 지식이 없는 일반인과 학생이다. 첫 검증은 성인 초보자로 시작하고, 미성년자 검증은 보호 절차와 기관 협력이 준비된 뒤 별도로 진행한다. 기술 용어 시험 대신 조건의 의미, 관계의 연결 방식, 규칙 변화의 영향을 설명하는 능력을 목표로 한다.

| 항목 | 기존 SQL 학습 | 새 개념 퍼즐 |
|---|---|---|
| 시작 질문 | 어떤 SQL을 써야 하는가 | 어떤 조건이면 누가 남고, 왜 그런가 |
| 기본 조작 | 문법 입력·실행 | 카드 선택·조건 묶기·연결·규칙 교체 |
| 결과 판단 | 예상 결과와 SQL 결과의 일치 | 예측과 관찰의 차이, 반례, 설명의 일관성 |
| 실수 피드백 | 구문 오류·오답 | 어떤 가정 때문에 이 카드가 빠졌는지 설명 |
| 창의성 | 다른 쿼리 작성 | 같은 목표의 다른 규칙, 목표 자체의 재설계 |
| AI 역할 | SQL 생성·설명 | 질문과 반례 제안, 설명 비교, 사람의 판단 지원 |
| 성취 | 문제 통과 | 새 상황에 개념 적용, 자신의 생각 수정 |

**검증 가설 H1**: 문법 부담을 줄이면 초보자의 첫 성공과 개념 설명이 쉬워진다. **H2**: 예측 후 비교가 정답만 보는 것보다 전이에 도움이 된다. **H3**: 구조화된 질문·답변이 자유 댓글보다 근거와 반례를 늘린다. 모두 아직 입증하지 않았다.

### 네 단계의 새 해석

- **Learn / 발견**: 생활 속 가상 상황에서 결과를 먼저 예측한다.
- **Practice / 실험**: 조건·연결·규칙을 바꾸고 차이를 확인한다.
- **Apply / 전이**: 다른 이야기와 데이터에서도 같은 원리를 설명한다. 내 DB 연결은 필수 단계가 아니다.
- **Assist / 도움**: 단계별 힌트, 용어 풀이, 반례 질문을 요청한다. 기존 Production Assist와 새 학습 도움말은 화면과 권한을 분리한다.

제품의 중심은 ‘예측 → 조작 → 관찰 → 설명 → 변형’이다. SQL 보기와 고급 도구는 선택 경로로 둔다. 기존 사용자의 SQL 학습 경로는 유지하며 점진적으로 전환한다.

## 3. Concept Puzzle v0.1 범위와 첫 5분

**제품 제안**: 3종 퍼즐마다 안내형·독립형·전이형을 하나씩 만들어 총 9개를 검증한다. 가상 도서관·동아리 같은 비민감 소재를 쓴다. 로그인·DB 연결·AI 키 없이 시작하며 AI가 없어도 정답 확인과 설명이 가능해야 한다. 공개 커뮤니티는 v0.1 출시 범위에서 제외하고 별도의 폐쇄형 파일럿으로 설계한다.

| 시간 | 화면과 실제 문구 | 사용자 행동과 피드백 |
|---|---|---|
| 0:00–0:20 | “조건을 바꾸면 누가 남을까요?” / `바로 해보기` | 수집 동의나 가입을 첫 성공의 조건으로 삼지 않는다. 기록은 기기에 저장됨을 짧게 알린다 |
| 0:20–1:00 | 6장 카드와 “빨강이면서 동그란 카드를 골라 보세요” | 먼저 카드를 선택한다. 실행 전에는 결과를 노출하지 않는다 |
| 1:00–2:00 | `내 예상 확인` / 입력·조건·결과 3단계 | A만 남는다. 오답 카드에는 충족하지 못한 조건을 글과 기호로 표시한다. 실패 점수나 시간 압박은 없다 |
| 2:00–3:00 | “그리고를 또는으로 바꾸면?” | A·B·C로 바뀐다고 예측한 뒤 실행한다. 바뀐 카드와 그대로인 카드를 나란히 비교한다 |
| 3:00–4:00 | “내 말로 이유 설명하기” / 선택형 문장·자유 입력 | “둘 다 필요”와 “하나만 있어도 됨”을 비교한다. 입력한 글을 AI에 보내는 기능은 선택 사항으로 별도 고지한다 |
| 4:00–5:00 | 다른 색·모양의 4장 카드에 같은 원리 적용 | 답과 이유를 확인한 뒤 `여기서 마치기`, `관계 연결`, `규칙 바꾸기`를 동등하게 제공한다 |

첫 5분에 3종을 억지로 모두 풀게 하지 않는다. 조건 탐정을 완료하고 나머지는 선택한다. 마지막 화면에는 “오늘 발견한 것”과 이어 할 위치만 제공하며 연속 접속 손실·순위·자동 재생을 넣지 않는다.

접근성 기준은 드래그의 버튼 대체, 키보드 순서, 스크린리더용 관계 목록, 색 외의 모양·텍스트, 동작 줄이기, 읽기 쉬운 문장이다. 시간은 안내 예시이며 강제 제한이 아니다. 잘못 선택한 이유를 공개하거나 학생 간 점수 비교에 쓰지 않는다.

## 4. 3종 퍼즐의 규칙과 채점

### 4.1 조건 탐정: AND/OR와 경계 조건

고정 카드: A=빨강·원, B=빨강·네모, C=파랑·원, D=파랑·네모, E=노랑·세모, F=초록·별이다. “빨강 그리고 원”의 정답 집합은 `{A}`, “빨강 또는 원”은 `{A,B,C}`이다. 또는은 둘 중 하나 이상을 포함하는 의미라고 명시한다.

사용자는 결과 집합 예측 → 조건 블록 조작 → 실행 → 차이 설명 순서로 진행한다. 정답은 집합 비교로 판정하고 순서는 무시한다. 설명은 ‘두 조건 모두/하나 이상’의 구분을 선택형으로 확인하고 자유 설명은 별도 피드백으로 둔다. 힌트는 카드 한 장의 조건만 펼친다. 같은 집합을 만든 우연한 규칙은 새로운 카드 세트로 다시 검증한다.

전이형에는 경계값 `10 이상`과 `10 초과`를 넣되 누락값은 별도 후속 콘텐츠로 다룬다. 실제 사람의 성적·외모·집단 속성으로 조건을 만들지 않는다.

### 4.2 관계 연결: 연결 키·다대일·누락

가상 회원 `{m1:솔, m2:별, m3:달}`과 대여 `{l1:m1:책A, l2:m1:책B, l3:m2:책C}`를 제공한다. 이름이 아닌 회원 ID로 연결하게 한다. “대여 기록이 있는 회원과 책”의 결과는 솔–책A, 솔–책B, 별–책C의 3행이다. “모든 회원을 남겨라”로 바꾸면 달–대여 없음이 추가되어 4행이다.

사용자는 연결선을 고르고 예상 행 수를 입력한다. 같은 회원이 두 번 나타나는 이유와 달이 빠진 이유를 설명한다. 채점은 연결 키, 결과의 중복을 포함한 행 수, 누락 설명을 분리한다. 표면적으로 같은 이름을 가진 회원을 추가하는 전이형으로 이름 연결의 반례를 확인한다. 선 모양뿐 아니라 표와 문장 목록으로도 제공한다. 그래프가 사회적 친밀도나 인과관계를 의미하지 않음을 명시한다.

### 4.3 규칙 바꾸기: 가정·목표·반례

가상 동아리 신청자 `{가:3점·기존, 나:3점·신규, 다:2점·신규, 라:1점·신규}`를 쓴다. 기존 규칙 “3점 이상이면 참여”는 가·나를 선택한다. 목표를 “최소 2명을 고르면서 신규 참여자를 적어도 2명 포함”으로 바꾸고 사용자가 규칙을 제안한다. 예를 들어 “2점 이상”은 가·나·다로 목표를 충족하고, “신규이며 2점 이상”은 나·다로 충족한다.

닫힌 규칙 블록은 결정적으로 목표 충족을 판정한다. 자유로운 아이디어는 ‘검토할 가설’로 보관하며 AI가 정답·공정성을 인증하지 않는다. 채점은 목표 충족, 제외되는 사례의 설명, 반례 제시, 대안 비교를 각각 기록한다. “2점 이상이 항상 좋은가?”에는 1점 신규 참가자 등 새 사례를 넣어 재검토한다. 가상 규칙에서 목표를 충족했다는 사실과 현실에서 공정하다는 의견을 분리한다.

### 공통 콘텐츠 계약과 유효성 검사

새 PuzzleSpec은 기존 SQL 문제 형식을 강제로 바꾸지 않는 상위 콘텐츠 계층으로 제안한다. 필드는 `id/version/locale/concept/story/data/rules/goal/expected/hints/counterexamples/explanation_rubric/accessibility/review_status`를 포함한다. 선택·연결·규칙 조작을 제한된 의미 모델로 표현하며 사용자 문자열을 SQL로 직접 실행하지 않는다.

발행 전 작성자와 다른 검토자가 데이터 일관성, 해 존재 여부, 대안 해 허용, 중복·정렬·누락 처리, 번역, 정답 유출, 접근성을 확인한다. 유한 데이터는 전수 계산으로 예상 결과를 확인한다. 문제·데이터·정답·채점기 버전을 시도 기록에 고정한다. ‘정답 없음’도 의도한 퍼즐이면 명시한다. 모순은 사용자 실패로 기록하지 않고 콘텐츠 오류로 회수한다.

## 5. 기존 자산의 재사용 경계

| 자산 | 재사용 제안 | 새로 필요한 것과 위험 |
|---|---|---|
| Learn/Practice 홈·문제 탐색·힌트·오답 기록 | 입구와 진행 구조를 재사용한다 | 문법 입력 중심 문구와 성취 모델을 바꿔야 한다 |
| practice pack·샌드박스·Command API | 고정 데이터 실행과 기존 SQL 경로를 유지한다 | 퍼즐 의미 모델과 채점 계약을 추가한다. SQL 정답 일치만으로 이해를 판단하지 않는다 |
| Query Graph | 입력→조건→연결→결과를 설명하는 표현을 참고한다 | 현재 SQL 인식 범위 밖의 퍼즐에는 별도 변환 모델이 필요하다. 일반 그래프를 자동 생성한다고 주장하지 않는다 |
| Result Intelligence·표·차트·설명 패널 | 표를 기준 증거로 두고 예측/실제 차이를 보여 준다 | 차트로 인과·공정성·현실적 진실을 추정하지 않는다. 지원하지 않는 경우 표와 텍스트로 돌아간다 |
| 웹/PWA·Capacitor·iOS SQLite | 공통 화면·콘텐츠·로컬 기록을 활용한다 | 새 퍼즐의 웹/iOS 동등성, 캐시 버전, 오프라인 콘텐츠 실행은 별도 검증한다 |
| Production Assist의 승인·감사 개념 | 명시적 승인과 이력 추적 원칙을 참고한다 | DB용 JSONL 기록을 다중 사용자 커뮤니티 감사 체계로 간주할 수 없다 |

개인 퍼즐은 로컬 완결을 우선한다. 참여형 기능은 인증·공유 저장소·권한·운영 도구·삭제 절차가 필요한 별도 서비스이다. 학습 기록을 기본 공개하지 않으며 SQL 실행 권한과 커뮤니티 권한을 연결하지 않는다.

## 6. 참여형 시스템: 검토 질문을 함께 다듬는 공간

### 질문과 답변의 단위

질문 카드는 검토하려는 주장, 유형(사실·의견·창의적 가설), 범위·가정, 사용 데이터, 알고 싶은 점, 근거, 반례 요청, 공개 범위를 포함한다. 한 게시물 안에서도 문장별 유형을 달리 표시할 수 있다. 유형은 AI 제안 후 작성자가 확인하며 사람이 수정할 수 있다.

답변은 **주장 → 근거/관찰 → 성립 조건 → 반례/한계 → 대안 → 남은 질문**으로 작성한다. 짧은 선택형 양식도 제공하여 글쓰기 능력이 참여 장벽이 되지 않게 한다. “모르겠다/추가 확인이 필요하다”도 정상 답변이다. 사람에게 답글을 달기보다 주장 카드에 근거·반례·대안을 연결한다. 무제한 대댓글, 인용 공격, 사용자 태그, DM, 팔로우, 공개 좋아요·팔로워 수는 제공하지 않는다.

예시 질문: “가상 동아리에서 2점 이상 규칙은 신규 참여를 늘리는가?” 사실 항목에는 주어진 4명 중 신규 2명이 선택됨을 표시한다. ‘좋은 규칙이다’는 의견, ‘다른 동아리에서도 참여가 늘 것이다’는 검증할 가설이다. 다수의 동의가 사실 판정을 대신하지 않는다.

### 상태 전이와 오케스트레이션

| 단계/상태 | 처리와 화면 | 책임·실패 시 동작 |
|---|---|---|
| 1. 초안 | 범위·질문 유형·근거·공개 대상 입력, 개인정보 경고 | 작성자가 공개 전 수정·취소한다. 로컬 초안은 전송 전 구분한다 |
| 2. 사전 검사 | 개인정보·위협·혐오·표적 괴롭힘·스팸·출처 부족·중복 가능성을 제안한다 | AI는 위험 범주와 해당 문장을 반환한다. 확률은 유죄 판정이 아니다 |
| 3. 표현 정제 제안 | 원문과 제안문을 나란히 표시하고 의미 변화 강조 | 작성자가 부분 수락·거절한다. 원문을 몰래 바꾸거나 비판·방언을 일률적으로 지우지 않는다 |
| 4. 공개 대기/사람 검토 | 폐쇄형 파일럿은 모든 질문과 답변을 발행 전 사람이 확인한다 | AI 오류·장애 시 초안을 보존하고 사람 대기로 보낸다. 자동 공개 우회는 하지 않는다 |
| 5. 게시/답변 모집 | 주제·미답변 여부·제출 순서로 유한한 검토 묶음을 배정한다 | 운영자가 같은 견해만 모이지 않는지 확인한다. 신원·성적·인기도로 추천하지 않는다 |
| 6. 구조화 | 답변을 근거·반례·대안 카드로 묶고 원문에 연결한다 | AI 분류는 작성자가 수정한다. 출처 링크는 실제 존재·관련성을 따로 확인한다 |
| 7. AI 요약 초안 | 합의된 관찰, 쟁점, 반례, 미확인 주장, 다음 실험을 분리한다 | 답변 ID·버전을 문장별로 연결한다. 새 사실·가짜 출처를 만들지 않는다 |
| 8. 사람 확인 요약 | 진행자가 원문 대조 후 발행하고 참여자는 오독 수정을 요청한다 | 소수 의견과 불확실성을 보존한다. 요약이 진실 인증서가 되지 않게 한다 |
| 9. 종료/재검토 | 질문을 종료하고 새 근거는 새 회차로 연결한다 | 끝없이 새 답변을 소비하게 하지 않는다. 중요한 수정은 이전 열람자에게 선택 알림을 준다 |
| 10. 신고/항소 | 모든 카드와 요약에서 신고·차단·처리 상태·항소 제공 | 이해관계 없는 사람이 재심한다. 삭제·변경된 근거는 요약을 ‘재검토 필요’로 전환한다 |

개인정보 노출이나 직접적 위협이 의심되는 콘텐츠는 범위가 좁은 임시 비공개로 격리할 수 있다. 이는 계정 벌점이나 유죄 판정이 아니며 자동 연장하지 않는다. 파일럿에서는 애초 사람 발행 전 대기이므로 노출이 없다. 이후 사후 게시를 도입하더라도 당직자가 1시간 내 확인하도록 설계하고, 검토 인력이 없으면 신규 게시를 멈춘다. 원문은 공개 복원하지 않고 작성자와 담당자에게 상태·사유·검토 기한을 알린다.

AI가 단독으로 경고 누적, 이용 정지, 영구 추방, 외부 신고를 결정하지 않는다. 중립화 제안을 거절하거나 AI 판단에 이의를 제기한 사실은 제재 근거로 삼지 않는다. 위험 콘텐츠를 ‘예의 바른 문장’으로 고쳤다는 이유만으로 허용하지도 않는다.

의학·법률·금융의 개인별 조언, 현실 인물의 의혹 조사, 자해·폭력 조장, 성적 착취 등은 초기 교육 커뮤니티의 주제 범위에서 제외한다. 위기 상황은 공개 토론으로 해결하려 하지 않고 훈련받은 책임자가 별도 대응 절차를 따른다. 신고 대상자를 공개적으로 심판하거나 미성년자에게 조사·중재를 맡기지 않는다.

정책은 금지 행위·예시·사유 코드·적용일·항소 경로를 쉬운 한국어로 공개한다. 중대한 위협에는 단계적 경고 없이 사람이 즉시 제한할 수 있으나 사유와 재심을 남긴다. 제재는 콘텐츠와 기간에 한정하고 비공개로 통지한다. 정정된 의견, 다수와 다른 의견, 신고 횟수만으로 불이익을 주지 않는다.

파일럿 목표 처리 기한은 긴급 노출 1시간, 일반 신고 2영업일, 항소 7영업일이다. 운영 시간·접수 상태·지연을 표시한다. 24시간 대응 체계가 없으면 운영 시간에만 신규 발행한다. 긴급 대응 인력과 독립 재심 담당자를 확보하지 못하면 참여형 기능을 개방하지 않는다.

## 8. 개인정보, 미성년자, 감사로그와 남용 방지

### 개인정보와 미성년자 기본값

개인 퍼즐의 진행 기록은 기기에만 두고 수집·동기화는 별도 선택으로 제공한다. 공용 기기에는 `내 기록 지우기`와 게스트 세션 종료를 제공한다. 커뮤니티 계정에는 가명과 최소한의 연령대·공간 권한만 보관하고 생년월일·신분증을 관행적으로 수집하지 않는다. 연령을 알 수 없으면 보호 수준이 높은 제한을 기본 적용한다.

미성년자는 승인된 폐쇄 공간에서만 참여하며 외부 성인과의 개인 접촉·프로필 검색·외부 링크 이동을 제한한다. 보호자·교사가 모든 사적 입력을 자동 열람하지 않도록 권한을 구분한다. 관할별 연령·동의·교육기관 책임·삭제 의무는 출시 지역과 실제 데이터 흐름을 확정한 후 전문 검토한다. 이 문서는 법적 준수를 인증하지 않는다.

외부 AI 전송 전 식별 정보를 제거하고 필요한 문장만 전송한다. 계약상 보존·학습 사용 제한을 검증하기 전 학생 콘텐츠를 보내지 않는다. 개인 퍼즐은 AI 없이도 이용할 수 있고 커뮤니티 참여는 별도 선택이다. 학습 데이터로 재사용하려면 별도 명시적 동의를 받는다.

### 데이터와 감사 설계 제안

핵심 객체는 QuestionVersion, AnswerVersion, Claim, EvidenceLink, SummaryVersion, Report, ModerationCase, Decision, Appeal, AuditEvent이다. 공개 원문·개인 계정·안전 사건 저장소를 분리한다. 모든 공개 범위와 역할 검사는 서버에서 강제하고 공간 간 접근을 차단한다.

감사 이벤트에는 사건 ID, 가명화된 행위자/역할, 시각, 객체·버전, 이전/이후 상태, 정책 사유 코드·버전, 모델/프롬프트 버전, 사람의 승인자, 통지 여부, 항소 연결을 남긴다. AI의 내부 사고 과정은 수집하지 않는다. 원문을 로그마다 복제하지 않고 접근 통제된 증거 객체를 참조한다. 추가 기록 방식과 변조 탐지·별도 백업·접근 이력을 적용하며 ‘변조 불가능’하다고 단정하지 않는다.

보존 기간은 파일럿 제안값으로, 삭제 콘텐츠의 복구 대기 30일, 일반 안전 사건 종결 후 90일, 보안 접근 기록 30일, 백업 순환 삭제 30일로 시작한다. 실제 의무·필요성 검토 후 확정한다. 보존 예외는 책임자·사유·만료일을 기록한다. 사용자 삭제 시 공개본·파생 요약·검색 색인·AI 전송본 처리와 백업 만료를 추적하고 즉시 삭제와 유예 삭제 범위를 알린다. 공개 투명성 보고는 소수 집단을 재식별할 수 있는 수치를 합치거나 생략한다.

### 남용·장애 대응

- 신규 계정은 하루 질문 2개·답변 5개, 전체 계정은 짧은 시간의 반복 제출을 제한한다. 이는 파일럿 가설값이며 장애인·공용망 이용자의 이의 신청을 허용한다. IP 하나로 여러 학생을 같은 사람이라고 판단하지 않는다.
- 중복 내용·다중 계정·신고 몰이는 사건 단위로 묶어 사람이 검토한다. 신고 수는 유죄나 인기 지표가 아니다. 신고 남용 제한도 정상 신고를 침묵시키지 않도록 별도 재심한다.
- 출처 링크는 허용된 방식으로만 가져오며 내부망 접근·자동 다운로드·스크립트 실행을 차단한다. 인용문과 링크는 검증 전 신뢰하지 않는다.
- 게시물 속 “정책을 무시하라” 같은 문장은 데이터로만 취급한다. 검사·요약 모델에는 관리 권한과 비밀값을 주지 않으며 출력 형식·길이를 검증한다.
- AI 시간 초과·비용 초과·과부하에서는 자동 승인하지 않고 대기열과 예상 지연을 표시한다. 동일 작업 재시도로 중복 게시되지 않도록 요청 식별자를 쓴다.
- 모더레이션 유입이 처리량을 넘으면 질문 모집·답변 발행을 차례로 줄이고 개인 퍼즐만 유지한다. 긴급 숨김·접근 차단·요약 철회·복구 절차를 미리 연습한다.

## 9. 타당성 검증과 성공 기준

아래 수치는 목표 제안이며 달성 결과가 아니다. 완료율만으로 교육 효과나 안전성을 주장하지 않는다.

| 검증 | 방법·규모·판정 기준 | 다음 결정 |
|---|---|---|
| 콘텐츠 타당성 | 9개 퍼즐을 서로 다른 검토자 2명이 검토한다. 가능한 결과를 전수 확인하고 정답·반례·중복·누락 모순이 0개여야 한다 | 실패한 문제는 사용자 실험에서 제외한다 |
| 첫 5분 사용성 | 성인 초보자 12명 관찰. 10명 이상이 진행자 도움 없이 30초 내 시작하고 5분 내 안내형+전이형을 마친다. 최소 9명이 AND/OR 차이를 자기 말로 설명한다 | 막힌 화면을 수정한 뒤 새 참여자로 재검증한다 |
| 3종 이해 | 유형별 예측·결과·이유를 별도 기록한다. 관계 연결에서 중복/누락, 규칙 바꾸기에서 대안 2개와 반례 1개를 설명하는지 본다 | 단순 정답률 상승만으로 통과시키지 않는다 |
| 학습 전이 | 후속 탐색 실험 30명 이상을 기존 SQL 입문/퍼즐 경로로 배정하고 사전·사후·7일 후 동형 과제를 비교한다. 퍼즐군 사후 점수 20%p 이상 상승, 지연 과제 70% 이상을 잠정 목표로 삼는다 | 표본이 작으므로 효과 크기·불확실성을 보고하고 인과 효과 확정은 후속 표본 설계로 미룬다 |
| 접근성·런타임 | 키보드·스크린리더·색상 구분 없이 완료하고 웹/iOS 동일 입력의 결과가 일치해야 한다. PWA 네트워크 실패와 iOS 오프라인을 각각 확인한다 | 실행 환경을 확인하기 전 오프라인 지원을 홍보하지 않는다 |
| 참여 품질 | 성인 20명, 2주 폐쇄 파일럿. 답변 80% 이상이 근거 또는 구체적 반례를 포함한다. 요약 50문장 표본에서 원문 연결 100%, 핵심 왜곡 0개를 목표로 한다 | 왜곡 발생 시 요약 자동 발행을 중단하고 사람 검수를 강화한다 |
| 안전·공정성 | 악성/정상/인용/방언을 포함한 합성 사례 100개 이상, 2인 독립 판정과 불일치 조정. 정상 콘텐츠 과잉 보류율 5% 이하를 목표로 유형별 누락도 함께 보고한다 | 중대 개인정보·표적 위협 노출 1건이면 확대를 중단한다. 0건도 안전 보장은 아니다 |
| 운영 가능성 | 질문·답변 1개당 검토 시간, 대기열의 가장 오래된 시간, 항소 번복 사유, AI 비용을 측정한다. 정한 처리 기한을 95% 이상 지킨다 | 인원 수보다 처리량에 맞춰 초대 수를 제한한다 |

측정은 동의한 테스트 참가자의 최소 사건 정보만 수집한다. 원문·개인 신원 없이 시작/예측/실행/힌트/설명/종료와 콘텐츠 버전을 기록할 수 있다. 영상 녹화와 자유 입력 수집은 각각 선택 동의를 받는다. 연령·언어·접근성 집단별 차이는 재식별 위험이 없는 표본에서만 분석한다. 체류 시간·일일 방문·댓글 수·연속 접속은 성공 지표로 쓰지 않는다.

## 10. 다음 행동과 의사결정 순서

기간은 담당자 확보 후의 계획 예시이며 이미 진행된 일정이 아니다.

1. **1주차, 제품 담당+교육 검토자**: 9개 퍼즐의 데이터·정답·반례·설명 기준을 확정한다. 첫 5분 화면 흐름과 접근성 대안을 종이/클릭 모형으로 만든다. 완료 조건은 2인 콘텐츠 검토 통과이다.
2. **2주차, 리서치 담당**: 성인 초보자 12명으로 사용성을 검증하고 설명 실패 원인을 수정한다. 미성년자 모집은 아직 하지 않는다.
3. **3주차, 구현 담당(별도 승인된 개발 작업)**: 퍼즐 의미 모델과 기존 API 연결을 기술 검증한다. 웹/iOS 공통 결과와 기록 삭제·오프라인 경계를 확인한다. 이 문서 PR에는 구현을 넣지 않는다.
4. **병행, 안전/개인정보 책임자**: 정책·권한표·신고·독립 항소·보존·사고 대응을 운영 연습한다. 최소 진행자 1명과 별도 재심 가능 인력, 운영 시간의 안전 담당을 확보한다. 확보하지 못하면 참여형 파일럿을 열지 않는다.
5. **후속 2주, 성인 폐쇄형 참여 파일럿**: 모든 발행과 요약을 사람이 확인한다. 새 학습 퍼즐 성공과 커뮤니티 운영 성공을 별도 판단한다.
6. **확대 결정**: 전이·운영 비용·안전 기준을 통과한 뒤에만 학생 대상 기관 파일럿을 검토한다. 공개 SNS형 확장은 자동 후속 단계가 아니다.

즉시 검토할 질문은 다음과 같다. 각 질문의 답은 사실·판단·가설을 구분해 기록한다.

- 목표 사용자가 ‘재미있었다’ 외에 어떤 개념을 다른 상황에서 설명할 수 있어야 하는가?
- 자유 입력이 주는 창의성에 비해 검사·모더레이션 비용이 감당 가능한가?
- 규칙 바꾸기의 목표를 누가 정하며, ‘공정함’에 관한 서로 다른 의견을 어떻게 보존할 것인가?
- AI 없이도 충분히 배울 수 있는가? AI가 필요하다면 어떤 실패를 줄이는가?
- 참여 공간을 열 책임자와 독립 항소 담당자가 실제로 있는가?
- 첫 출시 지역·연령 범위·기관 역할·AI 처리 계약·보존 기간을 확정할 수 있는가?

## 11. 남는 위험과 제한

구조화된 양식도 은근한 모욕·집단 배제·허위 출처·편향된 진행을 없애지 못한다. 중립화가 피해자의 표현이나 소수자의 말투를 지울 수 있고, AI 요약이 다수의 잘못된 결론을 강화할 수 있다. 작은 폐쇄 공간에도 권력관계와 교사 평가에 대한 압박이 생길 수 있다. 정답이 있는 퍼즐에서의 성과가 현실의 판단력·창의성 향상을 보장하지 않는다.

이에 따라 원문·반례·불확실성을 보존하고, 사람의 독립 재검토와 쉬운 탈퇴·삭제를 제공하며, 운영 인력을 넘는 규모로 확장하지 않는다. 안전 목표는 유해 행위의 예방·발견·회복 가능성을 높이는 것이며 ‘SNS 문제가 발생하지 않는다’는 약속은 하지 않는다.

외부 참고 원칙은 [eSafety Safety by Design](https://www.esafety.gov.au/industry/safety-by-design)의 서비스 책임·이용자 통제·신고/구제 설계와 [UNICEF Guidance on AI and Children](https://www.unicef.org/innocenti/reports/policy-guidance-ai-children)의 아동 안전·개인정보·공정성·설명 책임이다. 이 문서의 구체적 기한·숫자·권한·출시 관문은 CoQuery를 위한 제품 제안이며 해당 기관의 인증이나 법적 의무로 인용하지 않는다.

## 12. 실제 수행 상태

이번 작업에서는 이전 대화 조회, GitHub 플러그인을 통한 저장소 메타데이터·기준 문서 확인, main 복제와 기준 SHA 확인, 관련 코드·설계 문서 읽기, 이 한국어 기획 문서 작성을 수행했다. 제품 코드 수정, 퍼즐 구현, 사용자 실험, 안전 운영 테스트, 서비스 배포, TestFlight 업로드, merge는 수행하지 않았다. 원격 문서 브랜치·PR의 성공 여부와 링크는 최종 작업 보고에서 별도로 확인한다.
